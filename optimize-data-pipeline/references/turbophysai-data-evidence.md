## 2. 成组契约与受限路径

- **ACT 预取**。`lerobot_act.h2d_prefetch_stream` 显式依赖 `lerobot_act.nonblocking_h2d`。`_record_batch` 只遍历 Tensor、dict、list、tuple。保留 iterator 引用时，提前 break 不会触发 `finally`，调用方需要显式结束迭代。先验实际源 pin 状态，再测重叠。[ACT 组定义](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lerobot_act/catalog.py)
- **BEV 预取和几何**。`bevformer.geometry_sca` 联动 loader 的 `_bev_*` 元数据与 `encoder_forward`。缺字段时 `_prefetched_sca_inputs` 退到在线投影、mask 和索引构造。BEVFusion 的 loader wrapper 归档在 `bevfusion.training`，训练 wrapper 也接入了编译和布局。当前语料可定位 BEVFusion 的元数据生产端，消费路径待核实。两个项目都保留原验证 loader，跨模型复用时需要分别验证几何、预取和编译命中，并补显式线程/拷贝早退验证。[BEVFormer 组定义](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevformer/catalog.py) · [SCA 消费与回退](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevformer/geometry_sca.py) · [BEVFusion 组定义](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevfusion/catalog.py)
- **ACT 连续分片**。`set_epoch` 恢复保护和 BatchSamplerShard 连续迭代在同一组。校验非空 epoch、分片策略、全局 batch 对齐及偏移上限。向量化是另一独立组。[ACT 组定义](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lerobot_act/catalog.py)
- **OpenWAM ZeRO-2 前瞻编码（原 D7，受限／单模型参考）**。PR #27，模型基线 `0c9ed80d80`，DeepSpeed 基线 `b35d9eb01b`。基线 `deepspeed/runtime/zero/stage_1_and_2.py::DeepSpeedZeroOptimizer.step` 直接调用 `all_gather_dp_groups`。After `OnlineEncoder` 要求原生 Wan22Ti2v/VAE38/T5、全部冻结且 eval、参数位于 ZeRO 分组之外、grad accumulation 为 1、有 worker，且目标内部签名吻合。标准分支异步发起 collective，在计算流编码后等待，无预览时走原 gather。deferred 分支仍发起延迟广播，由下次 forward 按层等待。保存边界与 overflow 保留正常批次顺序，退出时还原 optimizer step。**版本兼容性待核对**，由通信专项主导，数据管线协同检查顺序与生命周期。[OnlineEncoder](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/online_encode.py)
- **正确性保护（非提速）**。BEVFormer 缺元数据保留在线重算路径。MapTRv2 的 per-loader fork 需要底层线程安全。OpenPI 的 CPU 归一化统计在示例脚本设零 worker，用来避免子进程丢失 Python 兼容补丁。GR00T 显式选择 CPU OpenCV 才进入兼容解码分支，其他配置走原解码器。上述路径的性能均未复测。[OpenPI 示例](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/model_examples/OpenPi/README.md) · [GR00T 解码适配](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/groot/compat.py)
