# 数值、显存、RSS 与性能验收

在改动前约定目标版本、权重/数据/种子、数值容差、最坏形状及显存和主机内存红线。分别记录 **开关状态、实际路径命中、数值与功能等价、端到端稳态提速**。把 OOM、显存预算与 RSS 趋势作为独立验收项。

## 路径与正确性

| 模式 | 命中证据 | 数值、功能与回退 |
| --- | --- | --- |
| M1 / M2 | 每层实际 AC、SAC 区间、选定算子前向/重放覆盖，必要时记录 compile 变体 | 对照输出、loss、梯度和参数更新。显式检查 inplace、别名、梯度累积与随机状态。涉及 dropout、随机深度或 RNG 政策变化时单独验证并约定容差。 |
| M3 | 训练入口的有效 `use_cache` 及 cache 是否分配、更新或返回 | 检查省略、显式 `None` / `True` / `False`、已有 cache，以及 eval prefill 和 autoregressive decode。 |
| M4 | 同 dtype 路径、混合 dtype 回退，切片是否引用原 storage | 核对多种动态尺寸、dtype、布局以及前后向结果。确认 clone 的额外分配是否被后续释放抵消。 |
| M5 | 实际跳过的分支和保留的输出契约 | 覆盖消费该输出的模型变体、辅助 loss、回调和 eval/推理，核对 RNG、状态更新及集合操作。成组回退调用标志、前向与解包。 |
| M6 / M7 | 对齐每 rank 的 GC/清缓存事件、步号以及分配器实际配置和统计 | 覆盖非稳态 profiling、保存/恢复、进程组安全点和动态形状。确认关闭后恢复到原版本的行为。 |

前后向按项目既有容差，检查 NaN/Inf。若有必要的慢路径，单标「正确性保护（非提速）」，用该路径负责的功能或正确性条件验收。

## 最坏形状显存与 RSS

- **减 AC 或放宽 SAC 前先核对余量**。覆盖最大序列、分辨率/帧数、完整 batch、反向、梯度累积窗口和可能叠加的预取、编译、保存阶段。分别记录启动、预热和可比稳态窗口的 `max_memory_allocated`、`max_memory_reserved`，在各窗口边界重置峰值统计，并在后端可用时记录 `num_alloc_retries` 差值。同点 allocated/reserved、分配重试和快照用于判断碎片。
- **缺数据时最小取证**。先读实际配置、已有峰值/重试和 OOM 的步号、rank、阶段、shape 与堆栈。有权限时用原 checkpoint 设置与最坏样本跑短对照，出现 OOM 保留现场；目标环境支持且获准后再采集快照。如外部快照 Skill 不可用，可照样比对分配重试、同点统计和出错阶段，快照细粒度归因列待验证。
- **观察 GC 冻结的进程内存**。在初始化、编译/缓存 warmup 后选明确安全点。多卡检查每个 rank 的计数含义、恢复路径和 barrier 次序。分别采 trainer 与相关 worker 的 RSS，覆盖数倍原尖刺周期或实际长跑窗口。持续增长时回退并排查缓存、引用与 worker 生命周期，RSS 走势仅作为信号。

## 稳态性能与回退

对照固定模型、数据、形状序列、预热、窗口、后端和并行设置，用无 Profiler 的运行比较中位数与吞吐。有 GC/清缓存抖动时追加 P95/P99、最大值、尖刺频率和慢 rank 对齐结果。报告同时注明峰值显存及应用的 RSS 阈值。编译、布局、算子或通信叠加场景按可独立开关消融，原子组记录整体收益。

| 改动生命周期 | 回退与核验 |
| --- | --- |
| 调用期局部无状态分支 | 关闭开关，验证原分支、输出和梯度恢复。 |
| 初始化安装的包装、替换前向、长期缓存或编译图 | 恢复原入口并清理相关缓存，按受影响范围重建模型或重启进程。含初始化与运行时契约的原子组一起回退，并重测 eval、保存与续训等受影响路径。 |
| 进程级分配器环境变量或已冻结 GC | 恢复环境/开关后以新进程验证。若 OOM、RSS 持续增长或正确性回归，先恢复已验收路径再继续比较。 |

缺目标 GPU 或依赖时，在授权范围内完成静态接入和可执行的 CPU/mock 边界检查。设备路径命中、设备数值、最坏形状峰值、OOM 边界和吞吐均标为未验证。只报告实际观测过的 RSS 场景。
