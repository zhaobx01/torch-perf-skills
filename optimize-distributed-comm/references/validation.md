# 多卡正确性、显存、无死锁与性能验收

先约定项目数值容差、峰值显存上限与多卡测试拓扑，再修改代码。严格区分四层结论：**配置/开关已开启 ≠ 通信重叠或流量削减真实命中 ≠ 多卡数值与无死锁等价 ≠ 端到端稳态提速**。

---

## 1. 多卡数值与功能正确性

在相同卡数、相同随机种子、相同数据顺序与相同 compile/精度配置下，对照开关关闭与开启：

- **通用要求**：各 rank 同步后的 loss、梯度范数与更新后权重在项目容差内一致（注意归约顺序或 `ReduceScatter` vs `AllReduce` 的浮点结合律可能引入极小舍入差，但不得出现发散、NaN/Inf 或某 rank 权重漂移）。
- **DDP（`C1`）**：
  - 关闭 `find_unused_parameters` / 开启 `static_graph` 后，覆盖训练中所有分支路径（含首步、梯度累积步、验证切换），确认无未归约参数报错且各 rank 权重逐位一致；
  - 关闭 `broadcast_buffers` 时，确认模型不含依赖同步更新的 BN/动态 buffer。
- **FSDP1 / FSDP2（`C2` / `C3`）**：
  - 分别记录开关前后各 rank 峰值显存（`torch.cuda.max_memory_allocated` 与 `max_memory_reserved`），确认不触发 OOM 或显存分配器抖动（`empty_cache`/碎片尖刺）；
  - 变更分片单元（`fsdp_layers_per_group` 或 `split_root_fsdp`）后，验证前向输出、梯度与参数分片完整性。
- **Owner 分片 + `all_to_all_single`（`C5`）**：
  - 覆盖参数维度**可整除**与**不可整除** `world_size`、参数数量小于和大于 `world_size` 的边界输入，确认各 rank 本地分片更新结果与原全量 `all_gather` 路径等价。
- **ZeRO-2 二级框架内部改写（`C6`–`C8`）**：
  - **门禁回退单测**：故意模拟版本不匹配或 helper AST 不匹配，确认拒绝安装并走回原路径（带清晰日志），绝不静默误装；
  - **均衡与偏斜 bucket 对照（`C7`）**：分别构造命中 `ReduceScatter` 与命中定向 `Reduce` 的 bucket，确认 owner 切片数值等价；
  - **旁路完整性（`C8` `deferred_gather`）**：完整跑通 `训练多步 → 切 eval → 保存 checkpoint → 继续训练 → 训练结束`，确认所有旁路均在读取参数前完成 `finish()`，无陈旧权重读取。

---

## 2. 分布式稳定性与 Checkpoint 往返

- **无死锁稳定性**：在目标卡数（至少 2 卡，验收建议 8 卡）上连续运行多步（覆盖梯度累积边界、eval 切换、checkpoint 保存步与动态长度/分支），确认无 NCCL/RCCL hang 或超时。
- **HIP / RCCL 专项**：若修改了通信 stream、新增了 `ProcessGroup` 或改动了 FSDP 包装，须在目标 HIP/RCCL 环境确认无多 stream 乱序死锁，并核查是否保留了 [triage-and-rccl.md](triage-and-rccl.md) 的 `R1`–`R3` 正确性保护。
- **Checkpoint 往返**：保存的权重与优化器状态（含 ZeRO-2 分片或 FSDP2 DCP）须支持用**关闭开关的基线代码**加载并续训一步，确认状态键名、形状与数值一致（反之亦然）。

---

## 3. 性能验收

- **先证通信指标真的改善**：用 `trace-bottleneck-report` 对比优化前后的 T5 通信表，确认目标指标确实按预期变化：
  - 重叠类（`C1`/`C2`/`C4`/`C6`/`C8`）：**暴露通信 ms 下降、重叠率%上升**；
  - 降次数类（`C3` 合并单元）：**集合调用次数下降、平均消息字节上升**；
  - 降流量类（`C3` 常驻、`C5`、`C7`）：**通信总时长与传输字节数下降**。
- **无 Profiler 同口径测速**：端到端提速必须用无 Profiler 的独立多卡测速确认，跳过充分预热步，报告多次/多步中位数、离散度及最慢 rank 步长。
- **单变量消融**：禁止将 `torch.compile`、同步消除、算子替换或 DataLoader 优化的收益混算到通信优化上；若 `C1` 与 `torch.compile` 同用（如 `optimize_ddp=False`），须单独对比开/关该开关的净差异。
- **显存与吞吐并报**：通信重叠和权重常驻常以显存换时间，交付报告必须同时列出**稳态吞吐变化**与**峰值显存变化**。

---

## 4. 按生命周期界定的回退与离线边界

- **必须重启进程并重建对象**：DDP/FSDP/ZeRO-2 包装、自定义 `ProcessGroup`、双缓冲/staging 显存池、优化器分片状态以及与 `torch.compile` 交互的编译图均绑定进程生命周期。**关闭开关回退时，必须重启训练进程并重新构造模型、并行包装与优化器**，绝不在同一进程内热切并行开关做 A/B 对照。
- **无多卡 GPU / 离线交付边界**：仅在单卡或无 GPU 环境下时，只可完成静态候选扫描、代码接入（含开关与版本/AST 门禁）以及单进程/mock 边界单测；必须在交付清单中明确标注“多卡数值等价、无死锁稳定性、峰值显存与通信重叠收益均未验证”。
