# 多卡正确性、显存、无死锁与性能验收

实施前约定数值容差、显存预算、目标拓扑和 checkpoint 要求。分别验证配置生效、实际路径命中、数值与功能等价和端到端稳态吞吐。对照保持种子、输入、卡数、compile、精度和有效 batch 一致。

## 1. 数值与命中

| 模式 | 命中检查与关键数值用例 |
| --- | --- |
| C1 | 查实际 DDP 构造值、used/unused 集合、梯度别名和 buffer 广播。覆盖梯度累积、条件分支和 eval 切换，比较各 rank 梯度、buffer 和更新权重。 |
| C2/C3 | 查实际限流、预取、权重常驻和分片单元。比较前向、梯度、参数 shard、FSDP checkpoint 与峰值分配/保留显存，覆盖显存不足时的回退。 |
| C4 | 查生效的 ZeRO stage、桶配置和归约流。开关已启用的配置仍须查看真正的归约发射和等待点。 |
| C5 | 逐 shard 对比 owner 路径和全量 gather，覆盖非整除、空 shard、小 batch padding 和代价门槛，确保各 rank 的分支与 split sizes 一致。 |
| C6/C7 | 模拟版本、签名、AST、布局或选项不匹配，验证拒绝安装和有日志的整组回退。验证连续复用两半缓冲、均衡/偏斜 owner 分支及 staging 扩容，并逐 owner 对照。 |
| C8a | 查 optimizer 是否在分片前正确 regroup、step 是否排空、失败状态是否阻止重用或保存。验证同布局 checkpoint 往返、缺失/不符清单拒绝与允许的原生 rank-count 回退。 |
| C8b | 分别验证 eager 按层等待和 compiled 提前排空。覆盖非联合 forward、eval、保存、结束和部分提交失败，核对旁路读取的权重与期待版本一致。 |

比较 loss、梯度和更新参数是否在项目容差内。归约顺序变更可能产生舍入差。评估关键张量及 clipping 边界，检查 NaN/Inf 和 rank 漂移。

## 2. Checkpoint 与多卡稳定性

- 在实际拓扑和目标卡数上覆盖多步、梯度累积、动态输入、eval、保存/恢复和退出。记录超时、序列或通信组异常。HIP/RCCL 验收见 [R1–R3](triage-and-rccl.md)。
- 同一配置的保存、加载和续训一步是基本验收。若用户要求开关双向续训，分别验证两向 checkpoint 兼容。改变参数组、分片或格式时记录兼容矩阵。GR00T C8a 的原生 rank-count fallback 拒绝流水 checkpoint。关闭开关须使用已验证兼容的原生 checkpoint，或先验证转换流程。
- 双缓冲、分片状态或在途 work 未复位时，拒绝保存或继续运行。通过进程重启和兼容 checkpoint 恢复到干净状态。

## 3. 性能与显存

- 按机制取证。重叠类比较暴露 ms 与重叠率，分组类比较同类集合次数与消息大小，权重常驻和 owner 路径核对消失/替换的 callsite、消息字节及 padding/回传成本。C1 的 unused 搜索、bucket copy 或 buffer 广播各自验收。
- T5 按 Trace 事件及可用标注给出次数、平均消息字节和算法带宽。报告采样窗口与字段覆盖，缺失则标注。总线流量须另外取证，不能从平均消息字节直接读出。
- 用无 Profiler 的独立多卡采样给出预热、步数/轮数、中位数、离散度及各 rank 峰值显存。对 compile、诊断同步、算子、在线编码等做单变量或显式分组消融，记录快路径与正确性回退各自的影响。

## 4. 生命周期回退与无 GPU 交付

- 关闭对应开关或原子组。改动已安装包装、ProcessGroup、优化器分片、缓冲池或捕获图时，先按原路径排空/清理，重启相关训练进程，按需重建并行包装和优化器并加载兼容 checkpoint。仅改运行期选项时按该 API 的生命周期验收，DCP、优化器分片与通信组切换不要在同一进程热切 A/B。
- 仅有单卡、CPU 或缺目标依赖时，交付静态接入与可执行的 CPU/mock 检查结果。多卡等价、稳定性、峰值显存、通信命中和端到端收益按实际证据标为未验证。
