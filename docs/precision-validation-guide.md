# 共享精度与数值验收指南（训练与推理）

本指南适用于所有涉及计算精度或数值契约变更的场景——包括 `opt-runtime-env` 启用第 1 类后端数学开关、各 `opt-*` 专项中的敏感层/融合/通信/缓存保护，以及需要修改模型或训练源码的**整模型 AMP 迁移、全局 `fp32_precision` / `set_float32_matmul_precision` 调整与 ROCm/HIP BF16 探测修复**。

> **核心原则**：严格拆分四层结论——**开关/配置生效 ≠ 实际低精度或保护路径命中 ≠ 数值与功能验收通过 ≠ 端到端稳态提速**。主动改变计算精度时使用项目约定容差；保留原精度契约的改写按原数值与功能要求验收。

## 1. 基线固定与路径确认

实施前记录并锁定：**目标硬件、PyTorch 与后端库版本、完整生效环境变量与覆盖顺序、模型权重、输入样本、随机种子与解码/训练超参**。

| 变更场景 | 必须核对的生效与路径证据 |
| --- | --- |
| **后端 TF32 / FP32 数学策略** | 记录最终进程环境、覆盖顺序与 PyTorch 数学策略；通过后端日志、生成代码或 Trace 确认目标 GEMM/Conv 实际进入预期数学模式（输入/权重仍为 FP32 不代表内部走了 TF32）。 |
| **整模型 AMP / BF16 探测修复** | 核对设备能力探测（ROCm/HIP 不得被 `torch.version.cuda` 单边门控静默回退 FP32；核对原生算子与通信前提）、autocast 入口边界，以及代表性算子的输入、累加与输出 dtype。 |
| **局部精度 hook 与编译缓存** | 核对实际 `torch.compiler.config.cache_key_tag` 或独立缓存目录，对比生成代码与运行 kernel，并用不满足条件的输入核对原路径回退。 |
| **敏感层保护** | 核对实际 forward、进入敏感子区的张量 dtype 与显式升宽（仅关闭 autocast 时确认输入未残留低精度），以及恢复给调用方的输出 dtype；局部关闭 `allow_tf32` 时分别保存 `matmul`/`cudnn` 原值并在 `try/finally` 中恢复。 |
| **通信、输入与持久化缓存契约** | 多卡通信核对 ZeRO-2 `communication_data_type` 与 FP64 梯度范数归约；输入与磁盘缓存核对字段、设备、数值 dtype、位存储格式（如 BF16 `int16` 往返）、缓存签名及非法输入报错分支。 |

## 2. 数值与功能验收

### 训练验收
1. **同输入单步**：固定初始权重、输入与随机条件，比较输出、loss 与梯度；检查 NaN/Inf、最大绝对误差、相对误差或余弦相似度，覆盖敏感层与 AMP 边界。使用 FP16 `GradScaler` 时核对溢出、跳步与恢复。
2. **短跑对照**：同初始化、样本顺序、随机种子、优化器与学习率计划，比较 loss 曲线、梯度范数与参数更新；需要时覆盖多 rank 与 checkpoint 保存/恢复。
3. **下游指标**：按约定数据集与口径核对 mAP、成功率等任务指标；若仅完成短跑，须明确标注长跑收敛与最终评测未验证。

### 推理验收
1. **代表性输入**：固定权重、预处理、随机种子或采样/解码设置，覆盖常见 batch、长度/分辨率及敏感边界；状态化模型补首次请求、连续请求与缓存重置对照。
2. **输出与任务**：检查 NaN/Inf、输出 dtype/shape 与约定误差，并核对关键业务指标（如分数误差、一致率、策略成功率）。带随机性时按同采样口径比较并记录样本数。
3. **回退契约**：核对关闭候选开关后的输出与 dtype 契约一致。

任一约定指标超界时，暂停扩大低精度变更，立即按第 3 节回退并记录可复现输入或步号。

## 3. 按生命周期回退

| 改动类型 | 回退与复验动作 |
| --- | --- |
| **进程级环境变量与后端状态** | 恢复基线实际值或显式 `unset`（含清除上层强制覆盖），必要时隔离 MIOpen/后端搜索缓存，在**新进程**复验基线数学路径与数值。 |
| **编译 hook 与生成缓存** | 卸载包装并恢复基线 `cache_key_tag` 或切换独立缓存目录，新进程核对重新命中基线产物。 |
| **源码内 autocast / 敏感层 / collate 开关** | 关闭开关或还原代码，复核输入/计算/输出 dtype；若已改变参数或优化器状态，从基线 checkpoint 重建恢复。 |
| **持久化缓存格式** | 写端、读端、签名与磁盘文件成组回退或重建，禁止新旧位表示混读。 |

## 4. 按需静态扫描工具

仓库保留 [scan_precision_candidates.py](scripts/scan_precision_candidates.py)（配 [selftest.py](scripts/selftest.py)）作为按需静态工具，用于在进行整模型 AMP 迁移、HIP BF16 适配排查或代码级精度审计时扫描 Python 源码与 YAML 中的 CUDA-only BF16 门控、显式 `allow_tf32=False`/`fp32_precision`、`autocast` 边界及缺少 `cache_key_tag` 的 TF32 hook：

```bash
python3 docs/scripts/scan_precision_candidates.py <项目文件或目录> [--json]
```

> 仅修改后端启动环境变量（不改源码）时，请直接使用 `opt-runtime-env` 及其 `scripts/scan_runtime_env.py`。
