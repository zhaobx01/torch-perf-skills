# 正确性、性能验收与按生命周期回退

先约定项目数值容差与测量口径，再修改代码。严格区分四层结论：**配置/开关存在 ≠ 路径与同步消除真实命中 ≠ 数值与功能等价 ≠ 端到端稳态提速**。

---

## 1. 数值与功能正确性

在相同权重、相同输入、相同随机种子与相同 compile/分布式配置下对照改写前后：

- **通用要求**：前向输出、loss、反向梯度逐位一致或在项目既有容差内，无新增 NaN/Inf，输出结构与 dtype 不变。
- **标量留设备（`P1`）**：`.item()` 改为零维张量 `.reshape(())` 时，专门核对混合精度/fp16/bf16 下后续算子的 dtype 提升规则是否变化（零维张量与 Python `float` 在部分 PyTorch 版本中提升规则不同）。
- **CPU 元数据与缓存（`P2`）**：覆盖缓存冷启动未命中、命中、缓存达上限淘汰、纯文本/多图/视频混合分支，以及不满足拦截条件时的原样透传路径。
- **动态形状与去重（`P3`）**：覆盖全 0、全 1、单元素、空张量边界；验证选中与未选中位置的反向梯度正确回传；删 `.unique()` 前核实输入确实无重复。
- **varlen 绕开封装（`P4`）**：分别测满足前提（如右 padding）与不满足前提（如左 padding、`past_seen_tokens > 0`），确认不满足时确实走回退且输出、梯度一致。
- **指标跳过与延迟读取（`P5`）**：
  - 梯度累积场景分别测 `grad_accum=1` 与 `grad_accum>1`；
  - 推迟 `.detach()` 到日志边界时，确认非日志步无显存泄漏（未保留计算图），且生产端/消费端成组启停；
  - 延迟一步读取时，确认日志步号与真实步一致，不误触发早停或 best-checkpoint 判断。
- **非阻塞拷贝（`P8`）**：核实主机侧张量确为 pinned；跨 stream 时核实已调用 `record_stream` 且消费前存在同步点（可通过临时移除同步点对照验证数据竞争风险，再恢复验证无错）。

---

## 2. 分布式与 Checkpoint 一致性

- **集合通信顺序不变**：同步消除不得改变各 rank 参与集合通信的顺序与次数；多标量合并归约后，各 rank 汇总值应与逐项归约一致。
- **多 rank 步号一致**：使用延迟一步读取时，确认所有 rank 读回的是同一步指标，避免不同 rank 错位。
- **Checkpoint 往返**：保存的权重与优化器状态格式不变；若改动触及优化器 step 计数或训练循环状态，验证保存→加载→续训一步结果与基线一致。

---

## 3. 性能验收

- **先证“命中且同步下降”，再谈墙钟加速**：用 [profiling.md](profiling.md) 或 `trace-bottleneck-report` 确认目标同步事件次数与对应 GPU 空闲时长确实下降；静态扫描命中或开关打开不等于真实生效。
- **无 Profiler 同口径测速**：带 `with_stack=True` 的 Trace 含显著额外开销，端到端提速必须用无 Profiler 的独立测速确认，跳过预热步并报告多次测量的中位数与离散度。
- **单变量消融**：禁止将 `torch.compile`、算子替换、channels-last 或精度改动的收益混算到同步消除上。
- **无收益或负收益如实记录**：若同步原本不在关键路径（GPU 未空闲）、固定形状引入过多冗余计算、或源张量未 pinned 导致未加速，如实汇报并回退，不隐藏权衡。

---

## 4. 按生命周期界定的回退与离线边界

- **常规回退**：保留默认可关闭的开关，关闭后恢复原代码路径与数值行为。
- **何时需要重启进程或重建对象**：
  - 仅修改局部函数条件开关且无持久化副作用 → 关闭开关即可生效；
  - 改动涉及**进程级环境变量/框架配置**（如 DeepSpeed `timers.throughput`）、**已安装的模块级/类级猴子补丁包装**、**跨步缓存（`LaggedMetrics`、位置编码缓存）**或**已捕获的 `torch.compile` 编译图** → 切换开关后必须**重启进程并重新构建模型/优化器**，避免残留状态污染对照。
- **无 GPU / 离线交付边界**：缺少目标硬件或运行环境时，可完成静态扫描、代码接入与 CPU/mock 边界单测，并在交付清单中明确标注“设备数值与性能未验证”，绝不把源码注释或静态分析写成已验证结论。
