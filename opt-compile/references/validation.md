# 正确性与性能验证

本文是包内完整的基本验证规范，不以其他 Skill、原始流程文件或历史案例源码为硬依赖。若本地已安装 `debug-graph-breaks` 或 `analyze-memory-snapshot` 可按需协同；缺少时按本规范与 [P4](compile-problem-patterns.md#p4) 继续验证。只有用户当前提供的目标项目才是验证对象；没有可用 Python/PyTorch/GPU 时可做静态分析和验证计划，运行正确性与 GPU 性能诚实标记为「未验证」，不自动安装环境。若本轮仅授权分析，下文运行与采集步骤仅作后续建议，不自动执行。

## 1. 五层生效核对与“注册 ≠ 调用点命中”

严格区分五层结论：**开关开启 → 匹配/包装 → 运行实际捕获 → 数值与功能等价 → 端到端稳态提速**，每层分别记「通过 / 失败 / 未运行」。

注册表里有目标、别名也覆盖了多个导入路径，只说明替换可以发生，不说明运行时调用点用的就是被替换的名字。验收时必须从调用点反查：

- 核对目标模型的实际代码路径，确认调用的是被注册替换的符号，而不是同模块另有的同功能实现、局部导入或已绑定的旧引用；同时区分类/实例/方法包装和原函数/改写函数，确认全局关闭变量是否也控制显式 `disable`。
- **反例（BEVFusion，见 [16 模型编译证据](turbophysai-compile-evidence.md#ev-p67)）**：`catalog.py` 注册了 `draw_heatmap_gaussian` 和 `gaussian_radius` 的编译替换及别名，但 `transfusion.py` 在 `get_targets_single` 中实际调用同文件的 `draw_heatmap_gaussian_cpu` 和 `gaussian_radius_cpu`。仅凭 catalog 只能写「已注册 / 别名覆盖」，「运行命中」必须由运行日志、调用计数或 Trace 证实。
- **重复层与嵌套编译**：区分包装创建次数、实际图数与运行命中，检查不同 driver、模块类型、输入与缓存归属。动态标记覆盖 `None`、`0/1`、已标记轴及 eager 输出传递；`compile` 与 `checkpoint` 组合需真实验证重算的外层引用、Tensor 副作用、梯度和参数更新，受控替身不能证明数值正确性。

## 2. 公平比较与 A/B/C 三组对照

已有 Trace 与 HTA 数据的窗口、分母、并集口径及环境核对统一复用 **`trace-triage`**（见 `trace-triage/references/metrics.md` 与 `trace-triage/references/hta-analysis.md`），本 Skill 不重复定义两套口径。

- **输入与状态一致**：使用代表性输入，记录 shape、stride、dtype、设备、train/eval、AMP、batch 和序列长度分布，不只测最规整尺寸。eager 与 compiled 使用相同起始参数、输入与状态；训练比较须恢复模型、优化器、梯度、buffer、随机状态和 scaler，不能依次训练同一模型后比较不同状态。
- **数值与随机性**：沿用项目容差或显式约定容差，检查结构、shape、dtype、输出、NaN/Inf；训练另检 loss、梯度与参数更新。随机算子可能因执行路径不同产生不同随机序列，按项目契约做可复现局部测试或统计验证，不禁用 dropout 冒充正确。
- **A/B/C 三组对照归因**：混合重构优先做 **A（原实现）/ B（重构后 eager）/ C（同重构 compiled）**——A/B 衡量重构影响，B/C 衡量编译影响；缺某组时说明结论限制。装饰器形式代码须设计可验证关闭路径，不臆断单个环境变量已禁掉全部编译。
- **隔离变量**：冻结输入、精度/TF32 策略、布局、通信、NUMA、数据加载、容器和后端配置。单机/多卡、训练/推理分别报告；推理 FPS 不能证明训练 iter 提速。DDP 比较说明同步点与聚合方法，不只取最快 rank。

| 场景 | 验收重点 |
| --- | --- |
| 固定循环、list/dict、多层预测 | 候选不能因语法被排除；跨层输出顺序、长度及梯度一致 |
| NumPy/PIL 随机增强 | eager 岛的随机性、概率、状态更新保持；不将其删除后计作 compile 收益 |
| CPU 匹配与设备往返 | 同一有效代价矩阵、标签/索引对应及返回对象正确，ties 按任务要求处理 |
| `force_fp32`/`auto_fp16` 包装 | 精度装饰器顺序、输入/中间 dtype、AMP、loss/梯度与溢出行为 |
| 可变 GT 与 padding | `N=0/1`/容量边界/超限；mask/length/索引映射一致，无虚假有效目标 |
| 原地操作、缓存/buffer | 输入副作用、alias、首次初始化与后续调用、train/eval 切换 |
| 父子都 compile | 实际捕获区域、子 mode 生效情况、重编译与边界碎片化成本 |
| 厂商与私有 options | 目标构建支持证据，禁用/启用对照，不向其他后端泛化 |

证据状态分开写：源码采用、用户报告有效、可关联日志支持、本次运行复测。每个性能数字附版本/输入/条件和日志位置。

## 3. 分开测量成本

1. **首次调用/冷启动**：说明是否新进程、编译缓存是否已存在；首次调用通常包含实际执行，不将其全称为纯编译时间。不删除用户全局缓存来制造冷启动。
2. **预热后稳态**：先预热，再多次测量，报告样本数、中心趋势和波动；不同 shape 覆盖各自的编译/预热。
3. **端到端**：保留真实数据处理与必要通信等业务指标，防止局部提速却整体无收益。
4. **内存**：在一致的进程/缓存条件下记录 allocated、reserved 与峰值指标；仅重置峰值计数不会释放已有分配，不把缓存残留算作某方案独有成本。

GPU 异步执行不能用未同步的 CPU 时间直接当 GPU 耗时；按测量目标使用设备同步后的墙钟时间或 GPU events，并说明范围。性能测量与 Profiler 采样分开：正式测速关闭 Profiler、数值检查与诊断日志。

若改动涉及全局 Inductor 调优（如 `TORCHINDUCTOR_LAYOUT_OPTIMIZATION`、`hip_triton_configs` 候选集扩展），除稳态耗时外，必须同时记录**首次编译/autotune 耗时增幅**与**非目标平台零侵入验证**。

报告 eager/compiled 的稳态时间、首次调用时间、峰值内存和变化；可估算回本迭代数（额外启动成本 / 每步节省时间），节省不为正时不报告回本。

## 4. 按需 AOT、重编译、包装与按生命周期回退

- **局部 AOT 与分桶验收（见 [16 模型编译证据](turbophysai-compile-evidence.md#ev-p2)）**：分别验证准备/导出、加载/权重绑定、实际命中与数值正确性，覆盖首次/连续片段、缓存重置与原地修改、尾块、非方形输入、支持的 batch/dtype/layout、未匹配变体、部分/全部准备失败及命中后执行异常；无梯度编码案例不证明训练反向兼容。分桶测试零、桶边界两侧、负值与超上限，保持真实有效长度及下游索引契约，不把桶容量当有效元素数；不把 AOT 查表与 Dynamo 重编译混为一谈。
- **包装与开关独立验收**：建立「目标符号 → 工厂 → 运行时条件 → 返回路径」映射，区分初始化关闭与启用后关闭；验证 Group 关闭是否恢复原项目已有 compile 入口。核对缺少 API、全局开关、Group 启用、独立 opt-in 的组合；将显式关闭、能力不足和未捕获异常分开报告，不把未捕获异常视为自动回退。受控替身仅证明包装控制逻辑，不代替真实 engine 与 Dynamo/数值/吞吐验证。缓存为全局状态时，测试环境须隔离和重置。
- **按生命周期界定回退**：
  - **纯调用期路由开关**（不保留已安装模块/类包装、不改全局 `torch._dynamo.config`、无编译缓存污染）：可直接关闭恢复原路径。
  - **进程级状态或已安装包装**：配置冻结后改参数、关闭大块编译或返回同一类对象均不保证撤销既有包装或独立小函数入口；涉及进程级环境变量、已安装模块/类包装、已捕获编译缓存或全局 Inductor 钩子时，**默认以独立新进程复验或按影响范围重建模型**，并验证 checkpoint 保存/恢复与 train/eval 切换。

## 5. 诊断、停止条件与验收用例建议

- **诊断与三项修复验收**：图中断按 [P4](compile-problem-patterns.md#p4) 处理，重编译转 P3，重复层/嵌套入口关联 P7；普通错误先调试，不用关闭编译掩盖。必要时使用 `TORCH_LOGS=graph_breaks,recompiles` 或 `TORCH_TRACE`/`tlparse`；日志有图中断不等于必须消除所有中断，须与实测影响挂钩。修复验收分三项并分别记录通过/失败/未运行：① 正确性（输出/loss/梯度/状态）；② 捕获（边界与剩余图中断/重编译，不按重复日志行数推算图数）；③ 性能（关 Profiler 与诊断日志后的首次调用、稳态耗时、波动与峰值显存）。
- **停止条件**：按实际影响、证据与修改成本筛选，低影响或收益未超过波动的候选记录原因后暂缓。失败时定位最小改动，按约定修复、缩小边界或回退；遵守任务预算，不无限重试，不静默改 `fullgraph`、删必要行为、放宽容差或开 `suppress_errors`。
- **行为验收用例建议**：
  - **仅分析请求**：项目源码不变，输出具体文件/符号和编译候选，说明无 Trace 时的证据限制。
  - **稳定模型的实施请求**：加入开关，eager/compiled 输出及梯度满足容差，提供真实计时命令和数据。
  - **包含 `.item()` 或数据相关分支**：定位具体问题，保持分支语义，按需与同步专项或 `debug-graph-breaks` 协同。
  - **多种 batch/长度**：报告重编译行为，比较边界与动态策略，不盲目固定 `dynamic=True`。
  - **无可用 GPU**：给出静态接入/方案与未验证清单，不编造速度与显存结果。
