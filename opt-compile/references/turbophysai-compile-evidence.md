## 二、按 P1–P7 精选跨模型机制要点

<a id="ev-p1"></a>
### 1. 编译范围与子系统粒度（P1）
- **异构多模态分粒度**：[lingbot_vla_v2](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_vla_v2/qwen3vl_compile_vision.py) 拆出 Vision 逐 block、Text 逐层、Action Expert 分支与冻结 Teacher 4 个独立开关；[openvla/compile_fsdp1.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openvla/compile_fsdp1.py) 对 FSDP1 包装的 LLM 层逐层编译（将 `checkpoint_wrapper` 留在编译单元外层，顺序为 `FSDP(layer) → torch.compile → checkpoint_wrapper`），对无 checkpoint HOP 的视觉塔整塔编译（原因来自 docstring，属「来源自述，未复测」）。
- **包装对象类型不互换**：[bevfusion/compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevfusion/compile.py) 并存 backbone 实例、模块类、检测头方法与小 helper 四类目标；[bevformer/compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevformer/compile.py) 并存图像特征阶段、Encoder 单层与 Decoder 整体。
- **阶段与局部编译（同质合并）**：FlashOCC（image/bev encoder、prepare_inputs、occ_train）、LeRobot-ACT（backbone + encoder/decoder）、DreamZero（VAE encode + ViT image encoder）、Sparse4D（ResNet/FPN + target）、PointPillars（nearest BEV IoU + anchor grid）按可独立验证的计算阶段分开关编译；LingBot-VA 在 [pointwise.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_va/pointwise.py) 与 [rotary.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_va/rotary.py) 对局部逐元素与实数 RoPE 函数使用 `torch.compile(..., backend='inductor', fullgraph=True, dynamic=True)`（单算子融合归因交算子专项 K4）。

<a id="ev-p2"></a>
### 2. 复杂外层、Helper 重建与局部 AOT（P2）
- **基线缺失 helper 必须追踪调用方重建**：[maptrv2/compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/maptrv2/compile.py) 通过 5 个基线调用方重建 8 个内部 helper（不得将 5+8 重复计作 13 个编译区域），并按 `(helper, mode)` 缓存。
- **局部 AOTInductor 与显式状态契约**：[cosmos-framework.patch](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/model_examples/Cosmos3/cosmos-framework.patch) 保留 VAE 外层切块/拼接调度，仅对重复核心做局部 AOT 导出，显式输入/输出状态缓存并按 `(shape, state)` 查变体表（无梯度前向案例不能证明训练反向可用）。

<a id="ev-p3"></a>
### 3. 重编译治理、分桶与定长 Padding 契约（P3）
- **定长 Padding 不得破坏 Dropout 语义（强耦合原子组）**：[groot/fixed_padding.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/groot/fixed_padding.py) 在 trainer 入口统一补齐宽度至 156 稳住 VL 图，同时 [groot/vl_padding_dropout.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/groot/vl_padding_dropout.py) 用 `@torch.compiler.disable` 的 `CollatorWidthDropout` 在原始 collator 宽度上执行 dropout 再 pad 回，严格保留随机语义。
- **分桶与同步/分布式联动**：[openvla/text_len_bucket.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openvla/text_len_bucket.py) 做文本长度分桶；[bevformer/geometry_sca.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevformer/geometry_sca.py) 对比了现场 GPU 分桶（仍有 `.item()`）与数据预取侧 CPU 分桶（无 GPU 同步）；MapTRv2 [assigner.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/maptrv2/assigner.py) 的静态 GT 补长与 DDP `static_graph=True` 在配置中要求成组同开或同关。
- **上限兜底非根因**：[cosmos-framework.patch](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/model_examples/Cosmos3/cosmos-framework.patch) 的 `set_torch_compile_options` 抬高 `recompile_limit >= 64`、`cache_size_limit >= 512`、`accumulated_cache_size_limit >= 4096` 并置 `use_duck_shape=False`，仅作已有分桶后的兜底而非消除特化根因。

<a id="ev-p4"></a>
### 4. 图中断、Dynamo-Safe 改写与局部 Eager（P4）
- **保留图外但修好周边破坏（正确性保护）**：[maptrv2/grid_mask.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/maptrv2/grid_mask.py) 将只读 PIL `np.asarray` 拷为可写 buffer、跟随输入设备并加 `torch._dynamo.disable`；[openvla/vision_timm.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openvla/vision_timm.py) 把 timm 中触发 Dynamo 内部断言的 `set(n)` 改写为等价 `list`；[openvla/compile_fsdp1.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openvla/compile_fsdp1.py) 设 `MixedPrecision(buffer_dtype=None)` 避开 fake tensor `set_` dtype 报错（均属版本相关背景，「来源自述，未复测」）。
- **编译选项前置探测与注册表隔离**：[dit4dit/action_compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/dit4dit/action_compile.py)（受限参考｜版本兼容性待核对）原地 `action.compile(options={"fallback_random": True, "alignment_asserts": False})` 保参数与 checkpoint key，并前置检查 `hasattr(config, ...)`（注释「来源自述，未复测」称避开 PyTorch 2.10 DAS 构建中 HCU FA 标量 8-byte 偏移误报 16-byte 对齐断言）；[groot/attention.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/groot/attention.py) 将 `AttentionInterface._global_mapping.flash_attention_2` 整体 `disable`。

<a id="ev-p5"></a>
### 5. 接入顺序、Checkpoint Key、作用域隔离与全局 Inductor 调优（P5）
- **动态解析框架类与 `._orig_mod.` 清洗**：[openvla/compile_fsdp1.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openvla/compile_fsdp1.py) 调用时动态查 `_fsdp_class()` 防止早绑定丢失 `fsdp_prefetch` 补丁，并在保存 checkpoint 时 `_partition_state_dicts` 去掉 `._orig_mod.`。
- **上下文隔离 `torch._dynamo.config`**：[pointpillars/optimize_ddp.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/pointpillars/optimize_ddp.py)（实现参考，基线待核实）用 `with torch._dynamo.config.patch(optimize_ddp=False):` 限定作用在训练循环内，不永久污染全局；通信侧独立验 backward overlap。
- **全局 Inductor Triton 启发式候选集与环境变量**：[lingbot_vla_v2/hip_triton_configs.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_vla_v2/hip_triton_configs.py)（实现参考，基线待核实｜受限参考｜版本兼容性待核对）仅在 `torch.version.hip` 下包装 `triton_heuristics.pointwise` / `_reduction_configs`，按 `size_hints` 过滤、核对 `fn.arg_names` 兼容并去重后前插大 `XBLOCK`（4096/8192）与 `waves_per_eu` 候选，保留原 configs 兜底；各模型 `configs/runtime*.yaml` 中的全局 `TORCHINDUCTOR_*` 环境变量清单见 [decisions.md](decisions.md#全局-inductor-环境与厂商后端配置)。

<a id="ev-p67"></a>
### 6. 注册≠运行命中、重复层复用与闭包缓存（P6 / P7）
- **经典反例（注册与别名均存在但运行未命中）**：BEVFusion `catalog.py` 注册了 `draw_heatmap_gaussian` / `gaussian_radius` 编译替换及别名，但 [bevfusion/transfusion.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/bevfusion/transfusion.py) 实际调用同文件的 `draw_heatmap_gaussian_cpu` / `gaussian_radius_cpu`——验收必须从调用点反查并区分“已注册 / 别名覆盖 / 运行命中”。
- **闭包区域按 `__code__` 缓存**：[openpi/pi0_compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openpi/pi0_compile.py) 针对基线 `pi0_pytorch.py` 每步构造的嵌套 `forward_func` 闭包，通过闭包定位 owner 模型并按 `(function.__code__, mode, direct)` 缓存编译结果，避免每步重复创建包装。
- **嵌套分派与单元维图复用**：[openwam/pointwise.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/pointwise.py) 在外层 `global_compile` 捕获中直接 eager 执行小函数避免嵌套特化，并用 `as_strided` + `mark_static` 统一单元维 stride；SAC `_call` 始终经 `torch.compiler.disable` 进入，薄分派器用私有 `skip_code` 仅作受限版本参考（版本兼容性待核对），不作通用默认。

## 三、本 Skill 显式排除项与交接边界

- **上游多 rank Profiler Trace 统计与 HTA 交叉校验**：归 `trace-triage`。
- **单算子替换、FlexAttention 局部调优、`custom_op` 注册（K6）与单算子 `@torch.compiler.disable` 回退 ATen（K9）**：归 `opt-kernel`。
- **2D/3D 卷积 `channels_last` 边界与 `PYTORCH_MIOPEN_SUGGEST_NHWC/NDHWC`**：归 `opt-layout`。
- **`.item()`/`.cpu()` 同步饥饿**：归 `opt-sync`。
- **DataLoader batch 级 H2D 预取与离线特征缓存**：归 `opt-dataloader`。
- **激活检查点（AC/SAC）覆盖范围、峰值显存与 GC 抖动**：归 `opt-memory`。
- **DDP/FSDP/ZeRO 集合通信重叠与 RCCL 顺序**：归 `opt-distributed`。
