# 样本等价、多流安全与性能验收

在 A/B 中锁定数据集、种子、分布式与训练配置，明确顺序契约及数值容差。逐项记录 **开关开启、路径实际命中、功能与数值等价、端到端稳态提速**。

## 1. 样本、分片与缓存

- **样本**。比较各字段的键、shape、dtype 和数值。D2 验证自定义容器、`cpu_only` 与内部 CPU 张量的 pin 状态。D1 BF16 子模式确认目标字段已在 CPU 端转换，下游走既有 BF16 路径，对照数值和精度。
- **样本顺序与恢复**。D3/D5 逐 rank、worker、epoch 验证覆盖、重复、顺序、边缘尾批与映射值。非零断点必须在 `set_epoch(0)` 之后仍恢复正确，涵盖合法/非法偏移与原路径的非 shuffle 配置。D4 还应检查 `skip_batches`、RNG 和 state dict 更新时机。
- **缓存**。在训练恢复后按真实权重匹配 VAE window 与 T5 prompt 键，抽样比较在线与离线特征。若离线缓存采用低精度位存储（如 BF16 以 `int16` 落盘并在读端恢复），成组验证写端、读端、dtype 签名与往返还原精度，严禁新旧格式混读。验证缺条、损坏、陈旧或中断重跑时的明确诊断与回退。核算磁盘、IO 和读盘导致的等待。

## 2. 进程、多流与资源

- **worker**。对目标版本检查零 worker 构造参数兼容、spawn 所需的可 pickle 构造参数与入口、worker 启动与干净退出。底层已有活跃线程或设备上下文时，单独验证 fork 的适用性。已配置的 seeding 需要另外核实 worker 分片效果。
- **流与主机缓冲**。检查实际可搬运的 CPU 张量是否 pinned，copy Event 是否被计算流等待，设备 Tensor 是否遍历并保活到实际消费完成，pinned 源是否在 DMA 完成前保持可读且未改写。校验空/单批、提前 break 且保留迭代器、异常、再次迭代及线程错误传播。
- **回退与成组**。关闭预取或缺前提时验证原调用链保持有效。联动生产/消费字段或 sampler 恢复保护时成组启停，检查缺字段回退和完整交付。同步、在线重算或保留低并发以保护正确性时，标「正确性保护（非提速）」。
- **资源**。按节点记录各本地 rank 和 worker 的实际 RSS，留意共享页重复计数，并检查容器内存、`/dev/shm`、锁页与设备峰值。连续 epoch 检查资源是否仍在增长。

## 3. 路径命中与收益

1. 用 Trace（`trace-triage` §3、§5）检查读批等待、主机同步、拷贝流、H2D/kernels 重叠、实际 H2D 字节及步首暴露时长。单一 `cudaMemcpyAsync` API 名称无法区分 pageable、pinned 与跟随的同步。ROCm/HIP 等后端按实际运行时事件核对。
2. 逐项消融 worker、pin、非阻塞、独立流、降 dtype 和其他配置，避免编译、通信和布局混算。降 dtype 同时看 CPU 转换耗时与端到端结果。
3. 充分预热后关闭 Profiler 做多次稳态 A/B，报告步数、step 时间中位数、P90/P99 与各 rank 最大耗时。

## 4. 按生命周期恢复

- 无状态纯函数替换可关闭开关恢复。worker 参数、collator 或 sampler 的构造变化需结束迭代器并重建 DataLoader。进程级环境及全局 pin 包装需重启进程。
- copy-stream 或线程预取需先停止入队、关闭迭代器并 join，在待完成拷贝结束后释放缓冲，再启用原 loader。检查早退与异常退出的实际清理动作。
- 缓存切换需重建带缓存状态的 reader/loader，并恢复 encoder 位置、eval 状态及在线取值。涉及 ZeRO-2 optimizer 的受限实现按其包装生命周期恢复。
- 缺目标设备或数据时，记录已跑的版本检查、静态、CPU/mock 验证，分别标明设备数值、多流安全、设备 H2D、真实负载资源峰值与端到端稳态收益的未验证状态。
