# 启动配置调优模式

按现有瓶颈和目标构建选路。具体取值见 [变量手册](env-catalog.md)，来源与证据级别见 [语料证据](turbophysai-env-evidence.md)，对照和回退见 [分轨验收](validation.md)。

| 模式与证据状态 | 触发信号和动作 | 前提与反例 | 最小验证 |
| --- | --- | --- | --- |
| **R1 数学路径** · 已核实 After 配置，部署基线待核实 | FP32 GEMM/Conv 占时高且允许改变内部数学精度。分别评估目标库的 TF32、BLAS 后端或 Triton 精度开关。 | 目标硬件和构建支持。OpenVLA accuracy 层会移除 MIOpen TF32 变量，CLI 又可显式写回。已有关闭或绕行先查历史和容差。 | 两个新进程核对相关变量及实际数学路径，分别报告任务容差和稳态性能。 |
| **R2 卷积搜索与布局** · 已核实 After 配置，基线运行环境待核实 | 卷积在关键路径、shape 与运行周期可代表实际负载时，隔离搜索模式或布局提示。 | 动态 shape 与短跑可能摊不平搜索。布局提示与实际张量 stride、包装和消费者一起核对；涉及改布局代码时由布局专项主导。 | 记录搜索数据库状态、首次和重复搜索、卷积路径及输入 stride，对比输出、显存和稳态收益。 |
| **R3 队列、PCIe 与分配器** · 分配器有双侧迁移证据，其余为构建/硬件受限配置 | 有分配重试、显存碎片或多 stream 争用线索时，从对应变量入手。 | 先确认瓶颈及 runtime/allocator backend。队列和 PCIe 参数需核对驱动、硬件和实际传输契约。配置迁移可保留原行为。 | 核对分配器统计、队列或 PCIe 路径信号，检查峰值显存、长尾步时与 Graph 兼容。 |
| **R4 集合通信与 CPU 线程** · 已核实 After 配置，手工拓扑受限 | rank 齐整且暴露通信高，或已有 CPU 争用证据时核对算法、线程与拓扑。 | 固定拓扑案例绑定实际卡数、互联与 rank 映射；涉及强绑定时由通信专项协同。慢 rank 先查数据、CPU 分配和其他等待。 | 用代表性多 rank 负载核对算法/拓扑、正确性与终止行为，记录 CPU 利用率和稳态吞吐。 |
| **R5 编译与缓存** · 已核实 After 配置；私有 hook 是受限实现参考 | 冷启动、反复编译或缓存串用有证据时，试点 autotune、并行度或隔离路径。 | 固定已有编译边界，改变生成代码的开关与 cache tag/目录一起核对。代码 hook 与环境默认精度联动时联合验证，涉及私有 API 先核对版本。 | 核对实际后端、生成产物与缓存命中；分别对比首编、缓存复用、稳态性能及适用数值容差。 |
