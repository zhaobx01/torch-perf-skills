## 跨专项契约与受限变体

- **嵌套 AC 与图分派**。OpenPI #29（Before `215abfb217`）的 `src/openpi/models_pytorch/pi0_pytorch.py` 中 `PI0Pytorch._apply_checkpoint` 还能包住外层图。After [pi0_compile.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openpi/pi0_compile.py) `wrap_pi0_compile` 仅在训练、外层 AC 已开启且 region 名命中时在直连/保留 checkpoint 间切换，其他调用以及禁编译环境保持原实现。独立记录外层和 M1 循环内部 AC。源码对薄 helper 按层号产生 Dynamo 变体的解释为来源自述，未复测。
- **SAC 受限实现与保护路径**。OpenWAM #27（Before `0c9ed80d80`）的 [sac.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/sac.py) `prepare` 要求 native Wan dual system joint self-attention、无 VACE，受选区域的模块不能各自编译。attention 策略检查受支持的 FA2/SDPA，以及 FA2 构建中的 forward 算子注册，未命中启用的 attention 算子或显式 extra ops 时分别报错。`_ReplayRegionMode` 依赖私有 `func_counter` 保存重放位置，版本兼容性待核对。SAC 和 checkpoint offload 在此实现互斥；关闭 SAC 后基线 `save_on_cpu()` 路径仍由 [mot.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/ports/mot.py) 保留。按「正确性保护（非提速）」核对配置拒绝、回退与梯度。
- **train/eval 遍历状态缓存**。DreamZero #42（Before `ab790c198f`）的 `WANPolicyHead.set_frozen_modules_to_eval_mode` 每次训练前向入口执行。After [train_mode_cache.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/dreamzero/train_mode_cache.py) 的 `train_wrapper` 缓存 mode、调参标志与直系子模块标识，`set_frozen_modules_to_eval_mode` 跳过已在 eval 的模块。[catalog.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/dreamzero/catalog.py) 把 `set_trainable_parameters`、`inject_lora_after_loading` 与失效钩子一起安装；深层模块替换或绕过入口切模式须显式失效。此案例的主要证据是 CPU 遍历路径。
- **保留周期性清理**。LingBot-VA #34（Before `7c6ffa9bfc`）的 `wan_va/train.py` 按 `gc_interval` 调用 `empty_cache()` 和 `gc.collect()`，After [train_sync.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_va/train_sync.py) 的 `train` 仍保留这两项和步级同步。微步 barrier 的调整归同步专项。LingBot-VLA-V2 #40（Before `be969b8fd1`）的 [profiling.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_vla_v2/profiling.py) 中 `handler_fn` 清缓存只在 profiler 回调，排查稳态热路径时先核对是否启用了 profiler。

## 缓存证据与交接

- **进程内冻结编码器输出**。DiT4DiT #28（Before `d8854a1171`）的 `DiT4DiT/model/modules/vlm/Cosmos25.py` 中 `Cosmos25FeatureExtractor._get_prompt_embeds` 每次调用文本编码器。After [cosmos_cache.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/dit4dit/cosmos_cache.py) 的 `_text_encoder_output_cache_is_safe` 要求冻结且 dropout 为零，命中前确保 encoder 处于 eval。其`_get_prompt_embeds` 仅保留最近一次精确 batch 的已 detach 输出。键包含 prompt、device、dtype 与最大长度。按数据/编码瓶颈交接，同时核对显存驻留、权重/设备变化和 `invalidate_text_encoder_output_cache_safety`。
- **有界视觉几何缓存与导出回退**。Cosmos3 #19（Before `9726697a83`）的 `cosmos_framework/model/generator/reasoner/qwen3_vl/qwen3_vl.py` 逐次算视觉位置与序列元数据。After [独立补丁](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/model_examples/Cosmos3/cosmos-framework.patch) 的 `Qwen3VLVisionModel._get_cached_aux` 对 device 和 grid 值用 64 项 FIFO；`torch.jit.is_tracing()` 时强制走 `_compute_aux`；同一补丁中的独立 HCU `_cached_aux` 另在 `torch.compiler.is_compiling()` 时绕过缓存。标为「正确性保护（非提速）」。LingBot-VLA-V2 #40（Before `be969b8fd1`）的 [qwen3vl_cache_gridTHW.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_vla_v2/qwen3vl_cache_gridTHW.py) `fast_pos_embed_interpolate` 使用上限 16 项的进程级位置表缓存。缓存键缺少构表使用的 `num_grid_per_side` 和 `spatial_merge_size`，跨模型配置复用前须核对。按位置元数据算子、图捕获或同步的主瓶颈交接。
- **两阶段离线落盘**。OpenWAM #27 的 [cache_vae_latents.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/cache_vae_latents.py)、[latent_cache.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/latent_cache.py) 与 [text_store.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/openwam/text_store.py) 涉及离线生成和训练端切换，归 `optimize-data-pipeline`。DiT4DiT 上述进程内缓存属于另一条路径。
- **并行拓扑**。LingBot-VLA-V2 #40 的 [split_root_fsdp.py](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/turbo_physai/optimizations/models/lingbot_vla_v2/split_root_fsdp.py) 和 LingBot-VA #34 的 `reshard_after_forward` 接入由 `optimize-distributed-comm` 主导，显存预算协同核算。
- **未核实为提速方案**。语料中查到 OpenWAM 的既有 CPU activation offload 路径，optimized recipe 的 [OpenWAM 说明](https://github.com/zhaobx01/TurboPhysAI/blob/corpus/all-models/model_examples/OpenWAM/README.md) 要求关闭 checkpoint offload 与 CPU optimizer offload。此次未查到将 CPU activation offload 或 ZeRO optimizer offload 作为已核实提速改造的案例。
